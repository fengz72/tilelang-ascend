## 2. 算子功能与数学定义

### 2.1 功能描述

在 LLM 推理的 Decode / Prefill 阶段实现多段掩码（Segment Mask）的 Flash Attention：

- 将逻辑序列划分为 N 段（典型 4 段：history / context / realtime / target）
- 每段使用不同掩码规则
- 支持 ragged batch（每个 request 长度不同，TND packed 布局）
- 支持 Paged KV Cache 前缀匹配（prefix matching）

### 2.2 数学公式

$$
\text{Output}[q, h, d] = \sum_k \text{Softmax}\left(\text{Mask}\left(
\frac{Q[q,h,:] \cdot K[k,h,:]^T}{\sqrt{d_{\text{head}}}}, \; \text{seg\_rules}, \text{seg\_offsets}
\right)\right) \cdot V[k,h,d]
$$

### 2.3 段掩码规则

| 规则 | 含义 | 可见范围 | 对角线可见 |
|------|------|----------|-----------|
| 0 (Causal) | 下三角因果掩码 | `q_pos + 1` | 无 |
| 1 (Full) | 全可见 | `seg_end` | 无 |
| 2 (Diagonal) | 对角线掩码 | `seg_start` | `q_pos`（自身可见） |

### 2.4 典型段结构

```
├── history  (causal)   ~1600-3200 tokens
├── context  (full)        8 tokens
├── realtime (causal)    ~5-700 tokens（可含多子段）
└── target   (diagonal) ~1000-2048 tokens
```

### 2.5 算法

采用 **Online Safe Softmax**（在线迭代 softmax），避免对全量 attention score 的物化存储：

```
初始化: O = 0, l = 0, m = -inf
对每个 KV tile:
  S = Q × K^T × sm_scale           # GEMM QK
  S = Mask(S, seg_rules)            # 段掩码
  m' = max(m, rowmax(S))            # 在线 max
  P = exp(S - m')                   # 安全 exp
  l = l * exp(m - m') + sum(P)      # 在线更新 ∑exp
  O = O * exp(m - m') + P × V       # 在线更新 O + GEMM PV
  m = m'
完成后: O = O / l                    # 归一化
```

## 3. 实现架构

### 3.1 编程模式

采用 **Expert 模式**（手动控制），关键 pass_configs：

```python
PASS_CONFIGS = {
    TL_ASCEND_AUTO_CV_COMBINE: False,   # 手动分离 Cube/Vector
    TL_ASCEND_AUTO_CV_SYNC:    False,   # 手动核间同步
    TL_ASCEND_AUTO_SYNC:       False,   # 手动核内同步
    TL_ASCEND_MEMORY_PLANNING: False,   # 手动地址分配
    TL_ASCEND_AUTO_SYNC_VS:    True,    # 仅保留 Vector 核内自动同步
}
```


### 3.2 双核流水线（Cube + Vector）

算子采用 **Cube/Vector 双核协作流水线**，通过 workspace（GM）进行核间数据交换：

```
┌─────────────── Cube 核（Scope C）────────────────┐
│  GEMM1: S = Q × K^T  → workspace_1 (C→V)        │
│  GEMM2: O = P × V    → workspace_3 (C→V)        │
│  K/V 加载：Paged Cache 或 live KV                │
└──────────────────────────────────────────────────┘
                       ↕ cross_flag 同步
┌─────────────── Vector 核（Scope V）──────────────┐
│  段掩码生成（基于可见性单调递增的快速路径优化）   │
│  Online Safe Softmax（max/exp/sum）              │
│  P → workspace_2 (V→C)                           │
│  O 累加 + 归一化 + 输出写回                       │
└──────────────────────────────────────────────────┘
```

### 3.3 关键 Tiling 参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `block_M` | 128 | Query 行 tile |
| `block_N` | 128 | KV 列 tile（= block_size） |
| `core_num` | 24 | A3 设备核数 |
| `num_stages` | 14 | KV tile 流水深度 |
| `cross_interval` | 2 | 跨核同步间隔（每 2 个 tile 同步一次） |
| `half_M` | 64 | 每个 Vector 子核处理的行数（block_M // 2） |

### 3.4 关键优化

1. **掩盖计算（Hiding Computation）**：在等待 Cube 核结果期间，Vector 核提前生成 Mask，利用算力资源
2. **可见性单调递增快速路径**：基于"首行完全可见则全块必然完全可见"原理，整块跳过 Mask 生成（`T.tile.fill(buf_2d, 0.0)`）
3. **双缓冲 L0A/L0B/L0C**：`l0a_s[2, ...]` / `l0b_s[2, ...]` / `l0c_s[2, ...]` 实现 GEMM 流水
4. **跨核同步聚合**：`cross_interval=2` 减少跨核同步次数
5. **手动地址规划**：`T.annotate_address` 精确控制 UB buffer 地址复用
6. **Paged KV Cache 支持**：通过 `block_table` 查询物理块，支持前缀缓存命中与 live KV 混合访问

### 3.5 内存层级使用

| 层级 | 用途 | 容量预算 |
|------|------|----------|
| L0A | Q tile（双缓冲）、P tile（双缓冲） | < 128KB |
| L0B | K^T tile（双缓冲）、V tile（双缓冲） | < 128KB |
| L0C | S 累加器（双缓冲）、O 累加器（双份） | < 128KB |
| L1 | Q/K/V/P tile | < 512KB |
| UB | acc_o / softmax 状态 / mask buffer / IO buffer | ~150KB < 192KB |
| GM | workspace_1/2/3（核间交换） | core_num × num_stages × block_M × block_N |

## 7. 接口说明

### 7.1 Host Wrapper 接口

```python
def mtgr_ragged_segment_attention(
    query,                  # [total_q, heads, dim] bf16, TND packed
    key,                    # [total_q, kv_heads, dim] bf16, TND packed
    value,                  # [total_q, kv_heads, dim] bf16, TND packed
    segment_offsets_i32,    # [batch, max_segs+1] int32, 段偏移
    segment_rules_i32,      # [max_segs] int32, 段规则 (0/1/2)
    q_seq_starts_i32,       # [batch+1] int32, packed Q 起始偏移
    matched_prefix_lens_i32,# [batch] int32, 前缀匹配长度
    match_mode,             # int, 0=无前缀/1=全前缀/2=混合
    key_cache,              # [num_blocks, block_N, kv_heads, dim] bf16, Paged K
    value_cache,            # [num_blocks, block_N, kv_heads, dim] bf16, Paged V
    block_table_i32,        # [batch, max_blocks] int32, 物理块映射
    block_size,             # int, 必须为 128
    max_request_len,        # int, 最大 request 长度
    sm_scale,               # float, attention scale
    output_snd,             # [total_q, heads, dim] bf16, 输出
    block_M=128,            # Query tile
    core_num=24,            # 核数
    num_stages=14,          # 流水深度
    kv_group=1,             # GQA group
    cross_interval=2,       # 跨核同步间隔
) -> output_snd
```

### 7.2 输入约束

| 约束 | 要求 |
|------|------|
| `block_size` | 必须为 128 |
| `head_dim` | 必须为 2 的幂（32/64/128） |
| `block_M` | 默认 128，需与 `block_size` 一致 |
| `core_num` | A3 设备 24 |
| `segment_rules` | 规则数组为常量，编译期确定 |
| `q_seq_starts` | 长度为 `batch + 1`，前缀和形式 |
| `matched_prefix_lens` | 0 表示无前缀匹配 |
